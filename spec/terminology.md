# FTXP Terminology

This document defines canonical FTXP terms used across the repository.

- **FTXP** — Faceted Taxonomy Execution Protocol; the complete protocol.
- **Canonical Execution Kernel** — the reusable instruction layer that executes FTXP. It is the direct successor to the historical “Prompt de Taxonomía Facetada”.
- **Execution Profile** — runtime configuration of an FTXP run.
- **FT-L / FT-S / FT-X** — light, standard, and exhaustive presets of the same Execution Profile.
- **Canonical Data Model** — logical record model used to represent candidates, concepts, taxonomy nodes, facets, relationships, evidence, validation, saturation, and baselines.
- **Canonical Template Set** — T1 Execution Template, T2 Record Template, and T3 Run Package Template.
- **FTXP Run** — one application of FTXP to a target.
- **FTXP Run Package** — the complete structured output of a run.
- **Candidate** — a discovered but not yet accepted conceptual or lexical item.
- **Canonical concept** — a validated concept represented by a preferred label and stable identity.
- **Primary hierarchy** — the main classificatory tree, built using coherent sibling classification criteria.
- **Facet** — an orthogonal dimension used to characterize concepts without overloading the primary hierarchy.
- **Material novelty** — new information that changes scope coverage, concept structure, interpretation, or a validated decision.
- **SAT-MAX** — material saturation state reached after the required zero-material passes and adversarial/independent challenge.
- **Freeze** — state in which applicable quality gates, SAT-MAX, regression, and unresolved-defect conditions all pass.
- **SSOT** — Single Source of Truth; the canonical source for a rule or artifact.
- **Reopening trigger** — a material condition that authorizes reopening a frozen baseline.
